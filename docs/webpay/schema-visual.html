02 · secuencia financiera

Cómo corre Webpay.

Webpay Plus normal tarjeta siempre en Transbank commit único status recuperable
COMPRADORRESKICHILE / NEXT.JSSUPABASETRANSBANKRECUPERACIÓNCIERRE
01 · navegador

Carrito

IDs de piezas + contacto + destino. Nunca precio ni estado.

02 · POST

/checkout/quote

Origen exacto · rate limit · payload ≤ 16 KiB.

03 · POST

/checkout/create

Precio, descuento y despacho recalculados en servidor.

04 · RPC atómica

create_checkout

order + items + reserva + intento. Todo o nada.

05 · SDK oficial

Transaction.create

buy_order + session_id + amount + return_url.

06 · transbank.cl

Webpay alojado

Tarjeta · banco · autenticación. Fuera de ReskiChile.

07 · GET / POST

/webpay/return

token_ws o variante timeout / abort. Máximo 4 KiB.

08 · lease

claim_processing

Un proceso obtiene commit. Duplicados reciben wait/status.

09 · SDK oficial

commit / status

Commit solo una vez. Después, recuperación por status.

10 · RPC atómica

finalize_webpay

AUTHORIZED + response_code 0 + monto + orden + sesión + stock.

11 · cookie privada

/checkout/resultado

Confirmado · rechazado · verificando. Refresco automático.

cada minuto

Supabase Cron

Bearer secreto desde Vault → /cron/payments/reconcile.

sin commit

Reconciliador

Reclama lease · consulta status · backoff · finaliza.

Confianza
El browser propone.

PostgreSQL decide precio, descuento, despacho, disponibilidad y total.

Inventario
Talla + origen + reserva.

Checkout elige sólo una ubicación capaz de completar todo el carrito.

Idempotencia
Un commit máximo.

commit_started_at convierte cualquier respuesta incierta en consulta status.

Autorización
Coincidencia completa.

AUTHORIZED + código 0 + monto + buy_order + session_id + producto retenido.

Kill switch
Cierra ventas, no pagos.

PAYMENTS_ENABLED=false mantiene callback, resultado y conciliación.

Datos tarjeta
Nunca entran al sitio.

PAN, CVV y autenticación viven enteramente en Webpay.
